交互请求或数据完成依据
Business_core ↔ Map Server业务 ID、草坪 / 通道属性、割草配置；编辑后的新旧 ID 对应轨迹、拓扑、属性和配置引用一致；文件写入分工待定
Decision → Map Server处理、检查、保存、合并 / 分割等异步请求资产处理 / 提交结果、失败原因及明确版本

失败处理建议：缺失 ID、悬空拓扑引用、版本冲突或保存失败时保留旧版本；Nav Map 构建失败不报告就绪。Decision 继续处理事件，按策略继续旧有效任务或停止。拓扑用于跨区域路由的最终消费者待讨论。

NON-BLOCKING ORCHESTRATION

Global → Decision → Local，交接由调度核心完成

Global 返回路径给 Decision，Decision 向 Local 下发执行；Local 反馈后由 Decision 决定是否重规划，两级 planner 不直接交互。等待结果是状态，不是阻塞调用；具体请求协议仍为建议。

  1. 发出请求关联请求标识，立即返回事件处理。
  2. 服务受理返回接受 / 拒绝；耗时工作由 server 执行。
  3. 持续处理事件Anomaly 统一异常、执行结果、取消与超时仍可进入。
  4. 异步结果驱动迁移匹配请求与当前状态，隔离迟到结果。
