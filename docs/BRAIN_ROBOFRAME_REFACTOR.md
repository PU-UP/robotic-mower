# Brain 对接单一 roboframe 的重构计划

本轮重构 Python Brain 原型、仿真与说明文档；以 [架构基线](ROBOFRAME_ARCHITECTURE_BASELINE.md) 为职责依据。真实 roboframe 的 C++ 算法、Foundation 设备接口及部署不在本轮范围。

## 保留与迁移

1. 保留 Brain 的业务任务、区域顺序、建图业务阶段、低电抢占、暂停、取消和显式恢复；保留命令去重、反馈时效与版本检查、故障锁存、建图提交确认。
2. Brain 只对接 roboframe 的任务反馈，不再等待 perception/map_manager/pnc 三方就绪或推断内部能力依赖。
3. 一个区域下发一次 `MOW_REGION`；沿边与覆盖由 roboframe 内部执行协调。下发稳定任务标识，使暂停、回充和恢复能够关联原作业记录。
4. 将旧算法目录中的有用地图、观测和路径数据模型迁入 simulation；使用单一 roboframe 替身。以仿真设备反馈验证刀盘未知状态与充电确认边界，不把替身写成真实能力实现。
5. 同步协议、场景、测试、回放页面和入口文档；旧的三进程当前设计不再作为实施依据。历史架构稿保留并明确历史性质。

## 验收

- 建图、割草、暂停恢复、低电回充续割、取消及故障恢复可独立重放。
- 旧版本、重复或过期反馈不能推进任务；无响应超时不能被后来反馈掩盖。
- Brain 不拥有区域内执行步骤或空间覆盖记录；同任务恢复不丢失替身中的已确认作业记录，新任务不继承旧记录。
- 导航到桩不能直接等同于充电；刀盘请求不能直接等同于实际切割。
- 所有 Python 测试、场景验收和回放状态检查通过。

## 基线与恢复

## 限制

本仓库中的 JSON 是可执行原型协议，不锁定生产接口。仿真中的轨迹、刀盘及充电事实是测试输入；实际反馈可用性、覆盖记录格式和持久化、真实 BT 与硬件联调仍待完成。

上述五步已完成。保留了原有业务状态分层、地图连通和通道折线校验，替换旧三来源反馈与 Brain 区域内任务切换；协议、场景、回放和文档已同步。原有未提交的服务器架构稿保持原样。

验收结果：69 项 Python 测试通过；14 个独立场景无失败检查；461 步回放状态检查通过；Git 差异格式检查通过。新增设备反馈与续作检查均为替身级测试，未运行实机或 WSL roboframe 联调。

## 提交前复审

审查按单个 Brain 实例和确定性离线仿真的当前用途进行，检查任务输入、状态归属、恢复、反馈、场景与文档，不将其视为生产部署审查。

- 自动回充原先直接拼接 ID，可能与用户任务同名，也未登记为已使用。现分配不冲突的 ID 并登记，避免挂起任务与回充任务混淆或后续复用；已验证冲突输入和取消后的复用拒绝。
- 自动环境原先把充电事实绑定到 DOCK 执行分支，任务成功退出后立即变成未充电。现由模拟设备单独保持接触事实，任务结束或 BATTERY_OK 不清除，离桩才清除；已验证任务完成、业务空闲和再次出发。
- 协议明确任务 STOPPED 不证明刀盘或车轮物理停转；暂停时保留刀盘 UNKNOWN/RUNNING 的设备反馈，不伪造停刀确认。相关边界已有测试。

当前代码未发现仍在运行的三来源就绪汇总或 Brain 区域内沿边/覆盖调度。历史架构稿仅作追溯，不恢复旧部署；实际 Foundation、系统许可、持久化及重启隔离仍按设计文档标记为未接入。
